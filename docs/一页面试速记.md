# 项目面试速记（一页纸）

> AIReport：基于 LLM 的公众号文章智能采集与总结系统。
> 速记按"链路 → 架构 → 机制 → 表 → 高频题 → 踩坑 → 命令"组织，考前快速过。

---

## 一、项目一句话链路（1 分钟自我介绍用）

定时任务 → 逐个公众号 → 通过**宿主机代理 + 已登录微信读书的 Chrome**，在阅读器页里发请求拿到**文章列表/正文** → 存进 **MySQL** → 定时调 **LLM** 按提示词生成单篇摘要/月度报告 → **Web 端展示 + 导出**。

## 二、架构与角色（每个"为什么存在"）

```
前端 Vue (web_ui) ──HTTP──▶ 后端 FastAPI(容器) ──SQL──▶ MySQL
                                │  读/写            Redis(缓存/队列状态)
                                ▼
                        宿主机代理 host_weread_agent.py(:9000)
                                │ CDP(Chrome调试协议)
                                ▼
                账号池: 每账号一个 Chrome(端口9222/9223, 各自扫码登录微信读书)
                                ▼
        在阅读器页执行 fetch('/web/mp/articles'...) 绕过微信读书动态签名
```
- **为什么抓取要"代理 + 真实 Chrome"**：微信读书的列表接口需要浏览器环境动态签名（x-wr-pa），纯 HTTP 请求拿不到；所以用 CDP 指挥已登录 Chrome 在阅读器页里发请求。
- **为什么账号池**：一个账号有频率限制（-2014/-2041 风控），多账号按公众号 bookId 哈希分摊，失败自动换号。
- **为什么正文有三条通道**：① 账号池 weread 通道（稳，需 Chrome 开着阅读器页）→ ② web 通道（Playwright 无头浏览器爬原文 URL，会被反爬拦）→ ③ api 通道（requests 直连原文 URL）。代码顺序：账号池 → web → api。

## 三、核心机制

| 机制 | 一句话 |
|---|---|
| 定时抓取 | jobs/mps.py 用 cron 调度，逐个公众号入任务队列 |
| 文章去重 | articles 表按 id（公众号-文章reviewId）check_exist |
| 正文补抓 | 后台"内容补抓队列"定期捞正文为空的文章重试 |
| AI 摘要 | 读 config_management 里 llm_api_url/key/model，逐篇调 LLM，写回 article.description |
| 图片防盗链 | 前端/后端把 mmbiz 图片改走 `/static/res/logo/` 代理（后端去 referer 拉图+缓存） |
| 部署 | Docker Compose：mysql / redis / singbox(代理) / we-mp-rss；宿主机代理独立跑 |

## 四、数据表速记

- `feeds`：公众号（全局共享，id=`MP_WXS_xxx`）
- `articles`：文章（content/description/content_html）
- `user_feeds`：用户↔公众号订阅关系（多用户看同一批号）

## 五、高频问题速答

- **前端后端怎么通信**：axios → URL（`/api/v1/wx/...`）→ FastAPI 路由 → 查库 → JSON → 前端渲染；前后端靠"路径+参数+JSON"约定衔接。
- **定时/并发**：任务队列多线程跑，每个公众号随机 sleep 防限流；账号池按哈希分摊。
- **LLM 设计**：提示词放配置文件（不改）；超时/失败记录跳过；批量脚本断点续跑（已生成的跳过）。
- **Docker Compose 耦合**：同一 yaml 自动进同一内部网络，服务名当主机名；环境变量传 DB/REDIS 地址；depends_on 控制启动顺序。
- **三层环境变量**：compose `environment:`(固定地址) + `.env`/`env_file:`(可变/敏感) + `config.yaml`(声明与默认值)；config.py 用 os.getenv 解析 `${VAR:-默认}`。

## 六、踩坑案例（现象 → 根因 → 结论）——你的王牌

1. **定时任务"显示成功却没抓到文章"**
   → 代理返回 `NO_READER_PAGE` 等**字符串错误**被解析成 code=0 当成功 → 0 篇文章却报成功。
   → `_raise_response_error` 改为"有 errCode 即抛错"，失败显形。
2. **文章图片不显示 / 显示"未经允许不可引用"**
   → ① 微信防盗链：mmbiz 图片带非微信 Referer 被拦；② `fix_html` 里 `remove_attributes=[{'src': ''}]` 空值导致**所有 `<img>` 被误删**；③ 微信懒加载真实地址在 `data-src`；④ 详情页直接渲染原始 content（带脚本 405）。
   → 归一化 data-src→src + 去掉误删写法 + 图片改走后端代理 + 详情页也走 fix_html。
3. **网页点菜单卡几秒**
   → `/qr` 等接口写成 `async def` 却内嵌阻塞网络调用 → 卡住 FastAPI 事件循环 → 全站排队。
   → 阻塞接口改普通 `def`（线程池执行）。
4. **CSV 批量导入"成功但列表不显示、不抓文章"**
   → 导入只写 feeds 表，没建 user_feeds 订阅、没触发抓取。
   → 导入时自动建订阅 + 对 update_time=0 的号触发抓取。
5. **文件夹文章加载慢（几百个号）**
   → 前端对文件夹里每个公众号发一次请求，N 次合并排序。
   → 后端新增 folder_id 参数一次 SQL 分页。
6. **只显示 101 个公众号 / 分页锁死到第 50 条**
   → 接口 limit 上限 100 截断；窄侧边栏页码按钮放不下。
   → 上限放到 1000 + 侧边栏 pageSize 1000；分页改"共N条+滑窗页码(每屏4个)"。
7. **大模型配置页 CORS 报错**
   → 浏览器直连 LLM API 被跨域拦（浏览器限制）。
   → 服务端脚本（容器内 httpx 直连）不受影响，照常用。
8. **`.env` 开关不生效**
   → `config.yaml` 读的是 `${GATHER.CONTENT:-True}`（**带点**），.env 里写 `GATHER_CONTENT`（无点）匹配不上。
   → 必须写 `GATHER.CONTENT=True`；排查用 `docker exec we-mp-rss-local env | grep GATHER`。
9. **账号池"移除再添加还是已登录、不出二维码"**
   → 旧 Chrome 进程未释放文件锁，profile 删除不干净 → 旧登录残留。
   → remove_chrome 用 pkill -9 + 等 3 秒 + rmtree 重试；spawn 强制 Xvfb 虚拟显示（不弹窗到本机）。
10. **微信 JS 在站内 405（page_utils/jsmonitor）**
    → 存的正文带着微信页面脚本，原样渲染执行。
    → fix_html 增加移除 script/link/head。

## 七、部署/排查命令速记

```bash
# 改代码后生效(关键! 不--build 会跑旧镜像)
cd ~/AIReport && docker compose -f compose/docker-compose.local.yaml up -d --build we-mp-rss

# 看容器状态/日志
docker ps
docker logs we-mp-rss-local --tail 50

# 宿主机代理(不走Docker): 改它要 pkill + 重启
pkill -9 -f host_weread_agent.py; sleep 2; cd ~/AIReport/tools; nohup python3 host_weread_agent.py > ~/weread-agent.log 2>&1 &

# 容器里跑脚本(用虚拟环境python)
docker exec -it we-mp-rss-local sh -c 'PY=$(ls -d /app/env*/bin/python 2>/dev/null | head -1); "$PY" tools/xxx.py'

# 从容器拷文件
docker cp we-mp-rss-local:/app/文件 ./
```
