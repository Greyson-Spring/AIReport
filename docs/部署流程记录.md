# AIReport（WeRSS）部署与运行手册

> 记录日期：2026-09
> 部署方式：**Docker Compose（容器）+ 宿主机代理（抓取）+ Chrome 账号池**
> 部署目标：公司服务器上的 Ubuntu（通过 MobaXterm SSH 连接）
> 适用：完整部署、日常运维、代码更新、数据备份

---

## 一、项目框架总览（先看懂整体）

### 1.1 系统架构

```
浏览器(前端 Vue, 编译后放 static/)
   │ http://服务器IP:8001
   ▼
┌─ 容器 we-mp-rss-local（FastAPI 后端, :8001）──────────────────┐
│   ├─ 读/写 → MySQL 容器 db-mp-local(:3306)  文章/公众号/用户   │
│   ├─ 用    → Redis 容器 we-mp-rss-redis-local(:6379)  缓存/队列│
│   └─ 抓取要数据时 → POST http://host.docker.internal:9000/fetch│
└──────────────┬───────────────────────────────────────────────┘
               │ (宿主机代理, 不在容器里!)
               ▼
┌─ 宿主机代理 host_weread_agent.py（:9000）─────────────────────┐
│   通过 CDP(Chrome调试协议) 指挥账号池里的 Chrome               │
│   (每账号一个 Chrome, 端口 9222/9223..., 各自扫码登录微信读书)  │
│   在"阅读器页"里执行 fetch('/web/mp/articles?...') → 拿文章    │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 组件职责

| 组件 | 在哪跑 | 端口 | 职责 |
|---|---|---|---|
| we-mp-rss（FastAPI） | 容器 | 8001 | 网站后端 + 定时抓取任务 + 提供前端页面 |
| mysql | 容器 | 3306 | 存文章/公众号/用户等 |
| redis | 容器 | 6379 | 缓存、任务队列状态 |
| singbox | 容器 | 7890 | 抓取网络代理 |
| **host_weread_agent.py** | **宿主机**（不在容器） | **9000** | **抓取的总开关：连 Chrome、执行 fetch** |
| Chrome 账号池 | 宿主机（Xvfb 虚拟显示） | 9222/9223… | 已登录微信读书的浏览器，抓取靠它 |

### 1.3 抓取链路（一句话）

```
定时任务 → 对每个公众号 → 容器后端 POST 宿主机代理(:9000)
  → 代理通过 CDP 指挥某账号的 Chrome → 在微信读书"阅读器页"执行 fetch 拿文章列表/正文
  → 返回给后端 → 存进 MySQL → 页面展示 / LLM 摘要 / AI 报告
```

**为什么必须"代理 + Chrome"**：微信读书接口需要浏览器环境的动态签名，纯 HTTP 拿不到；所以用已登录的 Chrome 在阅读页里发请求。

### 1.4 端口一览

| 端口 | 用途 |
|---|---|
| 8001 | 网站（浏览器访问） |
| 9000 | 宿主机代理（容器后端调用，**外部勿占**） |
| 9222/9223… | 每个账号的 Chrome 调试口 |

## 三、完整部署流程

### 第 1 步：安装 Docker（服务器）

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker $USER     # 重新连接 SSH 后生效
docker --version && docker compose version
```

### 第 2 步：传代码 + 解压

```bash
cd ~
mv AIReport AIReport_old_bak      # 旧项目备份(新代码有问题可回退)
mkdir -p AIReport
tar -xzf ~/ai-report.tar.gz -C AIReport
cd ~/AIReport
ls                                     # 应看到 web.py、static、compose、apis 等
```

### 第 3 步：配置 `.env`（关键，不进 git）

`compose` 里 `env_file: ../.env` 指向 `~/AIReport/.env`，**必须存在**。参考：

```bash
# 数据库(compose 里 mysql 初始化用)
MYSQL_ROOT_PASSWORD=rootpass123
MYSQL_DATABASE=we_mp_rss
MYSQL_USER=rss_user
MYSQL_PASSWORD=pass123456

# 微信读书凭据(抓正文/老通道用; 过期也不影响列表抓取)
WEREAD_COOKIE=
WEREAD_VID=
WEREAD_TICKET=

# 采集模式(关键)
GATHER_MODEL=weread_mp
GATHER.CONTENT=True
GATHER.CONTENT_MODE=api
GATHER.CONTENT_AUTO_CHECK=True
GATHER.CONTENT_AUTO_INTERVAL=59

# singbox 代理地址(抓取走它, 更不容易被风控)
PROXY_URL=socks5://singbox:7890
```
> 值不对会在启动后体现为"抓不到/404"，排查用 `docker exec we-mp-rss-local env | grep GATHER`。

### 第 4 步：启动容器（mysql/redis/singbox/we-mp-rss）

```bash
cd ~/AIReport
docker compose -f compose/docker-compose.local.yaml config --quiet && echo "配置OK"
# 正式启动(首次会拉镜像/构建, 10~30分钟, 可断点续)
docker compose -f compose/docker-compose.local.yaml up -d --build
docker compose -f compose/docker-compose.local.yaml ps        # 4 个容器 Up
docker logs we-mp-rss-local --tail 30                          # 看到 Uvicorn running :8001
```
> 首次启动后，容器内程序会**自动连库建表**（SQLAlchemy `create_all`）。

### 第 5 步：启动宿主机代理 + Xvfb + Chrome 账号池（**抓取的关键，容器之外的必做项**）

> 代理不在 Docker 里，是宿主机上的常驻进程；Chrome 账号也要在宿主机跑。

```bash
# ① 装/启动 Xvfb(虚拟显示, 让 Chrome 隐形运行, 不弹到你电脑)
sudo apt install -y xvfb
pgrep -f "Xvfb :99" || (Xvfb :99 -screen 0 1280x900x24 &)
sleep 1 && pgrep -af Xvfb

# ② 启动宿主机代理(端口9000; 账号端口默认 9222,9223, 可用 WEREAD_PORTS 改)
pkill -9 -f host_weread_agent.py; sleep 2
cd ~/AIReport/tools
nohup python3 host_weread_agent.py > ~/weread-agent.log 2>&1 &
sleep 2
ps aux | grep host_weread_agent      # 应只有一份 python3
curl -s http://localhost:9000/status   # 应返回 {端口: {...}}
```
> 开机自启（可选）：把上面 Xvfb + 代理两条写进 `/etc/rc.local` 或 systemd，避免重启服务器后代理不在了。

### 第 6 步：账号扫码登录 + 打开阅读器页

1. 浏览器打开网站 `http://服务器IP:8001` → 登录 → 进**账号池**页面；
2. 点"**添加账号**"→ 页面会显示该账号 Chrome 的二维码 → 手机微信扫码登录；
3. 用代理把该账号 Chrome 导航到一个**阅读器页**（保证抓取可用）：
   ```bash
   curl "http://localhost:9000/navigate?port=9222&url=https%3A%2F%2Fweread.qq.com%2Fweb%2Fmp%2Freader%2F1b742a6224d505f5758535f33303831363733383033e66"
   ```
4. 建议再添加第 2 个账号（9223），多账号按公众号哈希分摊、防限流。

> 代理报 `NO_READER_PAGE` = 该账号 Chrome 没开阅读器页，用上面 /navigate 命令导航即可。

### 第 7 步：验证

```bash
# 网站
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8001/     # 200

# 抓取链路(代理 + Chrome)
curl -s -X POST http://localhost:9000/fetch -H "Content-Type: application/json" -d '{"book_id":"MP_WXS_某个真实id","offset":0}' | head -c 200

# 页面
浏览器访问 http://服务器IP:8001 → 登录 admin/admin@123 → 点"更新"某公众号 → 能抓到文章
```

## 四、日常管理

### 4.1 容器

```bash
cd ~/AIReport
docker compose -f compose/docker-compose.local.yaml ps            # 状态
docker compose -f compose/docker-compose.local.yaml restart we-mp-rss   # 重启单个
docker logs -f we-mp-rss-local                                    # 实时日志
docker compose -f compose/docker-compose.local.yaml stop|start    # 停/启全部
```
容器归 Docker 托管，关 SSH 不影响运行；服务器重启后容器自动恢复（`restart: unless-stopped`）。

### 4.2 宿主机代理

```bash
# 改了 host_weread_agent.py 后必须重启代理(否则跑旧代码)
pkill -9 -f host_weread_agent.py; sleep 2
cd ~/AIReport/tools && nohup python3 host_weread_agent.py > ~/weread-agent.log 2>&1 &
curl -s http://localhost:9000/status
```

### 4.3 账号池

- 添加/移除账号：网站"账号池"页面操作（移除会清该端口 profile，重加需重新扫码）；
- 账号报错含义：`-2010` 登录失效 / `-2014` 限流 / `-2041` 风控 / `NO_READER_PAGE` 没开阅读页 / `chrome_down` Chrome 没在跑；
- 出现异常先 `curl -s http://localhost:9000/status` 看两个账号状态，再对症处理。

### 4.4 代码更新流程

```bash
# ① Windows: 改了前端先 npm run build 并覆盖 static(见2.2)
# ② Windows: scp 改动的文件到服务器(或整包 tar)
# ③ 服务器:
cd ~/AIReport
docker compose -f compose/docker-compose.local.yaml up -d --build we-mp-rss
# ④ 如果改的是宿主机代理: 按4.2重启代理
# ⑤ 如果改了 config.example.yaml/默认配置: 需重新构建镜像
```
> 改了代码必须 `--build`，否则跑旧镜像。

### 4.5 容器内跑一次性脚本（补正文/批量摘要等）

```bash
docker cp 本地脚本 we-mp-rss-local:/app/tools/xxx.py
docker exec -it we-mp-rss-local sh -c 'PY=$(ls -d /app/env*/bin/python 2>/dev/null | head -1); "$PY" tools/xxx.py'
```
> 容器内依赖装在虚拟环境 `/app/env_*`，必须用它的 python（裸 `python3` 没依赖）。

## 五、数据备份与恢复

```bash
# 备份(MySQL 全库导出到 ~/)
docker exec -i db-mp-local sh -c 'mysqldump -u root -prootpass123 --databases we_mp_rss' > ~/we_mp_rss.sql

# 恢复(重建干净库再导入)
docker exec db-mp-local sh -c 'mysql -u root -prootpass123 -e "DROP DATABASE IF EXISTS we_mp_rss; CREATE DATABASE we_mp_rss CHARACTER SET utf8mb4;"'
docker exec -i db-mp-local sh -c 'mysql -u root -prootpass123 we_mp_rss' < ~/we_mp_rss.sql
```

## 六、常见问题速查

| 现象 | 原因 / 处理 |
|---|---|
| 网站打不开 | 容器没起：`docker compose ... up -d`；或防火墙：`sudo ufw allow 8001/tcp` |
| 更新显示成功但没新文章 | 账号没阅读页(`NO_READER_PAGE`) → /navigate 导航阅读页；或代理没跑旧代码 → 重启代理 |
| 抓取报 -2014/-2041 | 限流/风控：停手等冷却，别猛打；多账号分摊 |
| 正文为空 | `GATHER.CONTENT=True` 是否生效(带点号)；或用 `tools/backfill_content.py` 补抓 |
| 图片不显示 | 应走代理 `/static/res/logo/...`；`docker compose ... up -d --build` 重新部署 |
| 列表很慢(几十秒) | 确认已部署最新 `apis/article.py`(不再读 content 大字段) |
| 改了 .env 没生效 | 环境变量在进程启动时注入 → 必须重建/重启容器 |
