# 前后端衔接与基础语法（小白版）

> 面向完全不懂编程语法的读者。用本项目真实代码讲解：前后端怎么连接、每个语法是啥意思、遇到问题怎么排查。

---

## 一、前后端到底是怎么衔接的

```
浏览器里的页面(前端)  --发请求-->  服务器上的程序(后端)  --查数据库-->  MySQL
前端拿到返回的数据  -->  渲染成你看到的列表/页面
```

完整 7 步：

1. 前端代码有个函数 `getSubscriptions({page, pageSize})`（定义在 `web_ui/src/api/subscription.ts`）；
2. 函数内部用 `http`（axios 工具）发出一条 HTTP 请求，实际地址：
   `http://服务器IP:8001/api/v1/wx/mps?offset=0&limit=100`
3. 请求通过网络飞到服务器的 Python 程序（FastAPI，监听 8001 端口）；
4. FastAPI 拿 URL 路径 `/api/v1/wx/mps` 去匹配后端接口（`apis/mps.py` 的 `@router.get("")`，前缀 `/mps`，挂在 `/api/v1/wx` 下）——**两边路径对得上，这就是衔接规则**；
5. 后端查数据库 → 拼成 JSON → 返回 `{"code":0, "data":{"list":[...], "total":128}}`；
6. JSON 通过网络飞回浏览器；
7. 前端 `http` 解包 JSON，把 `list` 塞给 `unassignedMpList` 变量 → Vue 检测到变化 → 自动重新渲染侧边栏。

**一句话规则：前端发"请求(URL+参数)"，后端回"数据(JSON)"，两边靠"路径和参数约定一致"衔接。**

## 二、URL 和路由 —— 前后端怎么"对暗号"

前后端是两个独立程序，唯一联系方式是网络消息，地址就是 **URL（网址）**。

```
http://服务器IP:8001/api/v1/wx/mps?offset=0&limit=1000
└───────┘ └────────┘ └────────────┘ └────────────┘
  协议      域名:端口      路径          查询字符串(参数)
```

- `?` 前面是**路径**（找哪个接口）；
- `?` 后面是**查询字符串**：`键=值` 用 `&` 连接（GET 的参数）。

完整 URL 怎么拼出来（两边各拼各的，最后必须对得上）：

```
前端:  http.ts 的 baseURL "api/v1/"  +  subscription.ts 写的 "/wx/mps"
     = /api/v1/wx/mps

后端:  core/base.py 的 API_BASE "/api/v1/wx"  +  mps.py 的 prefix "/mps"  +  @router.get("")
     = /api/v1/wx/mps   ✓ 对上了
```

后端挂载（`web.py`）：
```python
api_router = APIRouter(prefix="/api/v1/wx")   # 顶层前缀
api_router.include_router(wx_router)          # 挂上 mps.py 的 router(prefix=/mps)
```

`apis/mps.py`：
```python
router = APIRouter(prefix="/mps", tags=["公众号管理"])
@router.get("", summary="获取公众号列表")
async def get_mps(limit: int = Query(10), offset: int = Query(0), ...):
    ...
    return success_response({...})   # 返回 JSON
```

**规则：前端写的路径必须和后端注册的路径一致。** 这就是"契约"。

## 三、逐个语法讲解（用本项目例子）

### 1. import / export（文件之间互相取用）

- `export`：一个文件说"这个东西我愿意给别人用"；
- `import`：另一个文件说"我要用别处的这个东西"。

前端（JavaScript）：
```ts
// http.ts
export default http          // 导出 http 对象

// subscription.ts
import http from './http'    // 使用 http.ts 导出的 http
```

后端（Python）：**没有 export 关键字，顶层定义的变量/函数默认都能被 import**。
```python
# apis/mps.py
router = APIRouter(prefix="/mps")   # 顶层变量

# web.py
from apis.mps import router as wx_router   # 隐式导出, 直接 import
```

> 类比：export = 把商品摆上货架；import = 从货架取货。

### 2. 对象（键值对）

```ts
const http = axios.create({
  baseURL: 'api/v1/',   // 键: baseURL, 值: 'api/v1/'
  timeout: 100000,
  headers: { ... }
})
```
对象 = 一个装着多个"命名字段"的盒子，`键: 值` 往里装，用键取。

### 3. const / let（定义变量）

- `const`：定义后不能再改；
- `let`：可以改。
```ts
const allFeeds = allFeedsRes.list || []   // 一旦赋值, 不再改
let unassigned = allFeeds.filter(...)     // 后面可能重新赋值
```

### 4. 箭头函数

```ts
const handleMpPageChange = (page) => { ... }   // 简写的函数定义
// 等价于 function handleMpPageChange(page) { ... }
```

### 5. async / await（等网络结果但不卡页面）

发请求要花时间，如果傻等页面就卡死。于是：
- `Promise` = "取餐小票"：请求发出去了，先拿张票，结果好了再通知；
- `async` = 标记这个函数里能用 await；
- `await` = "在这儿等结果回来再往下走"（只这一处等，页面别处照样能用）。

```ts
const buildLeftSidebarData = async () => {       // async: 函数内可用 await
  const [folderListRes, allFeedsRes] = await Promise.all([...])   // await: 等结果
}
```

### 6. Promise.all（并行发多个请求，一起等）

```ts
const [folderListRes, allFeedsRes] = await Promise.all([
  getFolderList(),                                     // 请求1
  getSubscriptions({ page: 0, pageSize: 1000 })        // 请求2
])
```
- 两个请求**同时**发（并行，不排队）；
- `await` 等**两个都回来**；
- 结果按顺序放进数组：第一个进 `folderListRes`，第二个进 `allFeedsRes`。

### 7. 数组三兄弟：filter / map / slice

- `filter`：筛选（留下符合条件的）；
- `map`：转换（每条变个样子）；
- `slice`：切片（切一段出来）。

```ts
let unassigned = allFeeds.filter(feed => !allArchivedFeedIds.has(feed.id))  // 筛掉在文件夹里的
unassignedMpList.value = unassigned.map(feed => ({ id: feed.id, name: feed.name, ... }))  // 转格式
paged = unassignedMpList.value.slice(start, start + pageSize)  // 切当前页10条
```

### 8. computed（自动重新计算的值）

```ts
const pagedUnassignedMpList = computed(() => {
  const start = (mpPagination.value.current - 1) * mpPagination.value.pageSize
  return unassignedMpList.value.slice(start, start + mpPagination.value.pageSize)
})
```
依赖的变量一变，它自动重算——点分页列表立刻更新，不用手动刷新。

### 9. 类型注解与可选链（TypeScript）

```ts
params?: { page?: number; pageSize?: number; kw?: string; status?: number }
```
- `?`：可选的（可以不传）；
- `params?.page`：可选链——`params` 不存在就不崩溃，返回 undefined；
- `(params?.page || 0)`：`||` 或——左边是假值就用右边（page 没给按 0 算）；
- `...(... ? {...} : {})`：展开运算符 + 三元表达式——条件成立就把 status 加进对象，否则不加；
- `http.get<SubscriptionListResult>(...)`：泛型，给编辑器"响应数据形状"的提示，运行时不影响。

### 10. axios 与 http.ts（发请求/收响应的工具）

axios = 别人写好的"发网络请求"库。项目单独写 `http.ts` 把 axios 配置一次（叫"实例"），全项目复用：

```ts
const http = axios.create({
  baseURL: 'api/v1/',    // 所有请求自动加前缀
  timeout: 100000,       // 超过100秒算超时
  headers: { 'Content-Type': 'application/json' }
})
```
- **请求拦截器**：请求发出前必经的门——自动贴登录令牌（Authorization）；
- **响应拦截器**：收到响应后必经的门——解包 `{code,data}`，`code===0` 时只把 `data` 给你。

HTTP 请求方法（动作）：`GET`（要数据，参数放 URL）、`POST`（提交数据，参数放请求体）、`PUT`（更新）、`DELETE`（删除）。
axios 对应：`http.get()`、`http.post()`、`http.put()`、`http.delete()`。

HTTP 请求头（附加说明，不是 baseURL/timeout）：`Content-Type`（请求体格式）、`Authorization`（身份令牌）、`Accept`（接受什么格式）、`User-Agent`（哪个客户端）、`Cookie`（登录状态）。

超过 timeout 时长：axios 放弃请求，判为失败，走错误处理分支。

## 四、那条变量链（数据从网络到页面）

```
allFeedsRes → allFeeds → unassigned → unassignedMpList → pagedUnassignedMpList
 原始响应        数组        过滤后        响应式变量          计算属性(切页)
```

| 变量 | 是什么 | 干什么 |
|---|---|---|
| `allFeedsRes` | 后端返回的原始响应 | 装着全部公众号数据 |
| `allFeeds` | 数组 | 取 `.list` 拿到公众号列表 |
| `unassigned` | 数组 | 过滤掉在文件夹里的，剩"未分类" |
| `unassignedMpList.value` | 响应式变量 | 存最终列表，模板直接渲染 |
| `pagedUnassignedMpList` | 计算属性 | 按当前页切出要显示的 10 条 |

## 五、后端怎么接住请求并返回

```python
@router.get("", summary="获取公众号列表")
async def get_mps(limit: int = Query(10), offset: int = Query(0), ...):
    ...
    return success_response({...})
```
- `@router.get("")` 装饰器 = 给函数贴标签："有人 GET 这个路径时运行我"；
- FastAPI 自动把 URL 里的查询参数装进函数参数（`?limit=1000` → `limit=1000`）；
- `success_response(data)`（`apis/base.py`）返回标准信封：
  ```python
  {"code": 0, "message": "success", "data": data}
  ```
- FastAPI 自动把字典转成 JSON 发回。

**怎么知道数据在哪个 key？**
1. 读后端函数返回：`success_response({"list":[...], "total":128})` → 数据在 `data.list`、`data.total`；
2. 前端拦截器已拆一层：`code===0` 只返回 `data`，前端直接用 `allFeedsRes.list`；
3. 泛型类型 `http.get<...>` 也会提示字段。

**验证**：F12 → Network → 点请求 → Response，能亲眼看到 JSON 结构。

## 六、可复用的排查框架（页面不对时的标准流程）

**核心思想：分清楚是"数据不对"还是"显示不对"，逐层往下排除。**

| 步骤 | 做什么 | 判断 |
|---|---|---|
| 0. 看数据 | F12 → Network → 找到请求 → 看 Response JSON | 数据对但显示错 = 前端渲染问题；数据本身就错 = 后端问题；没请求 = 前端问题 |
| 1. 试接口 | 服务器上 `curl "http://localhost:8001/api/v1/wx/mps?limit=200"` | 跳过前端直接问后端要数据 |
| 2. 查库 | SQL 直接查数据库 | 确认数据本身对不对（数据层） |
| 3. 追调用链 | 用 grep 搜变量名 → 找赋值函数 → 找 API 函数 → 找后端路由 | 定位到具体一行 |

**三个必会工具**
1. **grep 搜索**：按关键词（函数名、变量名、接口路径、页面标题）在代码里搜——第一武器；
2. **F12 → Network**：看前端发了什么请求、后端回了什么——判断前后端问题的分水岭；
3. **curl / SQL**：跳过前端测后端、跳过后端查库——逐层隔离。

## 八、cookie
cookie相当于网站发过来的会员卡。当扫码登录某个网站时，该网站就会在浏览器存入一个cookie(标明你是谁)。之后每次请求该网站，浏览器就会自动出示这张卡，网站一看这个卡就知道这是登录用户，就给数据。
但是cookie是会过期的，出示过期的cookie，网站是不认的

## 九。代理
代理（host_weread_agent.py）只是个"遥控器"，负责指挥 Chrome 去抓数据。重启代理 = 只是把"遥控器"重启一下，Chrome 本身没动：
- Chrome 进程还开着，页面还停着；
- 登录状态存在 Chrome 自己的"用户数据文件夹"里（~/.weread-chrome-9222、~/.weread-chrome-9223），和代理进程无关，代理重启不影响它。
所以 pkill host_weread_agent.py 只是把代理进程关掉（端口 9000 暂时没响应），Chrome 里的登录完全不受影响，重启完代理继续能用。
唯一的小影响：代理重启后，账号池页面的状态会重置成 unknown（因为状态记在代理内存里），等下次抓取后会自动恢复正常显示。两台 Chrome 都不用重新扫码。
